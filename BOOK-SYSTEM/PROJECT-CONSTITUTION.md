# قانون اساسی پروژه کتاب

## 1. هدف

این مخزن مرجع اصلی تولید و نگهداری کتاب دانشگاهی «مبانی تحول دیجیتال هوشمند» است. هدف، تولید محتوای فارسی دانشگاهی، تشریحی، کاربردی و قابل‌به‌روزرسانی با تکیه بر شواهد معتبر و پژوهش روز است.

## 2. موتور هوش

در نسخه پایه پروژه فقط یک موتور هوش برای پژوهش، تحلیل، نگارش و بازبینی استفاده می‌شود: GPT-5.6 Luna در ChatGPT.

مدل دیگری اجازه جایگزینی متن اصلی کتاب را ندارد مگر اینکه در آینده این قانون به‌صورت صریح بازنگری شود.

## 3. روزآمدی

اطلاعات مربوط به روندها، فناوری‌های نو، استانداردها، قابلیت مدل‌ها و یافته‌های جدید باید هنگام تولید یا بازبینی با Web Search بررسی شوند. حافظه مدل به‌تنهایی منبع روزآمدی محسوب نمی‌شود.

## 4. منبع حقیقت

GitHub منبع حقیقت پروژه است. متن فصل‌ها، شواهد، منابع، تصمیم‌های سردبیری، وضعیت تولید، نسخه‌ها و خروجی‌های قابل انتشار باید در مخزن ثبت شوند.

## 5. اصل Evidence-first

هر ادعای مهم علمی، آماری، زمانی یا فنی باید به یک منبع قابل ردیابی متصل باشد. ادعای بدون پشتوانه یا باید حذف شود یا با برچسب مشخصِ «فرض/تفسیر آموزشی» ارائه شود.

## 6. اولویت منابع

ترتیب ترجیح منابع:

1. استانداردها و اسناد رسمی نهادهای معتبر
2. مقالات داوری‌شده و مرورهای نظام‌مند
3. کتاب‌های دانشگاهی جدید و معتبر
4. اسناد و گزارش‌های تخصصی صنعتی با روش‌شناسی روشن
5. منابع قدیمی برای مبانی تاریخی و نظری

قدیمی‌بودن به‌تنهایی دلیل رد منبع نیست؛ اما منبع قدیمی نباید پایه ادعای جدید معرفی شود.

## 7. استقلال تعریف‌های کتاب

اصطلاحاتی که در ادبیات تثبیت نشده‌اند، مانند «Intelligent Digital Transformation» یا «AI-Native Organization»، باید صریحاً به‌عنوان تعریف عملیاتی یا چارچوب آموزشی کتاب معرفی شوند، نه استاندارد رسمی یا حقیقت تثبیت‌شده.

## 8. نقشه راه و انسجام بین فصول

سرفصل و نقشه راه `BOOK-SYSTEM/BOOK-ROADMAP.md` مرجع بالادستی کتاب است. هیچ فصل مجاز نیست بدون بررسی اثر آن بر فصل‌های مرتبط، ساختار یا دامنه مفهومی خود را به‌طور اساسی تغییر دهد.

هر مفهوم اصلی باید یک `canonical_home` داشته باشد. فصل‌های دیگر آن مفهوم را به‌صورت کاربرد، توسعه یا ارتباط با موضوع خود ادامه می‌دهند و از تعریف‌گذاری مجدد جلوگیری می‌شود.

`BOOK-SYSTEM/TRACEABILITY-MATRIX.md` برای ردیابی ورودی، خروجی و وابستگی مفاهیم بین فصول الزامی است.

## 9. کیفیت آموزشی

هر فصل باید علاوه بر صحت علمی، برای یادگیری طراحی شود: اهداف یادگیری، توضیح مفهومی، مثال، مقایسه، کاربرد سازمانی، محدودیت‌ها، جمع‌بندی، پرسش تحلیلی و تمرین.

## 10. کیفیت نگارشی

زبان کتاب فارسی، دانشگاهی، روان و تشریحی است. اصطلاح انگلیسی مهم در نخستین کاربرد داخل متن فارسی معرفی می‌شود. از ترجمه لفظی مبهم، جمله‌های بیش از حد فشرده و ادعاهای قطعی درباره موضوعات نوظهور پرهیز می‌شود.

## 11. تصاویر

هر تصویر باید ارزش آموزشی مشخص داشته باشد. تصاویر تزئینی ممنوع‌اند. برای نمودار تولیدشده در پروژه، توضیح و وضعیت تولید ثبت می‌شود.

## 12. تولید مرحله‌ای

هیچ فصل یا کتابی لازم نیست در یک نوبت کامل شود. هر نشست می‌تواند بخشی از پژوهش، نگارش یا بازبینی را انجام دهد. وضعیت کار باید پیش از پایان هر نشست ثبت شود تا ادامه کار بدون اتلاف context ممکن باشد.

## 13. توقف امن

اگر محدودیت استفاده، قطع ارتباط یا خطای ابزار رخ داد، آخرین state، منابع تأییدشده، ادعاهای باز و وظیفه بعدی باید در GitHub ثبت شده باشند.

## 14. ممنوعیت «سبز کاذب»

سبزشدن GitHub Actions به‌تنهایی به معنی تأیید علمی محتوا نیست. انتشار فقط پس از عبور از Quality Gates علمی، آموزشی، ارجاعی، انسجام بین‌فصلی و فنی مجاز است.

## 15. انتشار

Markdown منبع اصلی است. DOCX و PDF مصنوعات مشتق‌شده‌اند و باید از همان Markdown تولید شوند تا امکان بازسازی کامل وجود داشته باشد.

## 16. نسخه پایه

نسخه پایه این معماری با فصل اول به‌عنوان Pilot اعتبارسنجی می‌شود. تا پذیرش Pilot، اجرای جزئیات فرآیند تولید قابل اصلاح است؛ اما نقشه راه و قرارداد انسجام باید حفظ شوند مگر با تصمیم صریح معماری.
